## What I found: git is unusable here, not just gh

`street-work/.git` is a worktree pointer file:

    gitdir: C:/Users/mattm/Documents/street/.git/worktrees/street-work

That's an absolute Windows path into the *other* checkout (`street`),
which isn't the folder connected to this session, and -- the actual
blocker -- this agent's shell is a sandboxed Linux VM with zero view of
the Windows filesystem (confirmed: no `/mnt/c`, no drive letters, nothing).
So no `git` command resolves at all: not `status`, `log`, `branch`,
nothing. Requesting access to `street` too wouldn't help, since a literal
`C:/Users/...` path still can't resolve inside a Linux VM either way.

This is almost certainly the same root cause behind Infrastructure's
`gh auth status` failure and missing-remote-URL problem from its own first
run today (`hq/infrastructure/reports/2026-10-23.md`), and matches the
line in my own agent definition about `gh` "cause not yet understood" --
it's one structural cause, not two separate flukes. Opened in
`questions.md` with a recommendation (make `street-work` a standalone
clone with its own `.git` + remote, not a worktree).

I deliberately did not: hand-edit `.git` internals to patch around it, or
write the new app code straight onto disk with no git to branch from --
both felt too likely to corrupt real history or land files on whatever
branch happens to be checked out, which is exactly what "never commit
directly to work or main" is guarding against even without a literal
`git commit`.

## What I built instead: the full office page, drafted and ready

Everything lives in `hq/product/drafts/office-page/` (own `NOTES.md`
inside with the full detail). In short:

- **New file** `lib/admin-hq.ts` -- typed data access for all five
  `hq_*` tables, following `lib/admin-state.ts`'s exact shape
  (`hasSupabaseCatalog()`/`isMissingTableError()`, never a raw client).
- **New pages**, one per nav item from the charter: `app/admin/hq/page.tsx`
  (Today -- stat tiles, latest GM brief, open-questions preview,
  department list), `.../inbox/page.tsx` (Inbox -- all questions,
  open/answered/all filter, same pattern as `app/admin/activity/page.tsx`'s

  `.../departments/[id]/page.tsx` (one department's questions/goals/recent

  `/admin/forbidden` otherwise -- same gate as Activity. All reads
  `noStore: true` and degrade to an info `Banner` instead of crashing if
  the tables aren't synced yet.
- **Strictly read-only**, per the charter -- no answer-submission form.
  Logged a goal for the real two-way sync that would need before that's
  safe (GM's nightly sync currently rebuilds `hq_questions` fresh from
  each department's `questions.md` every run, which would silently wipe
  any answer typed into the page).
- Used the shared `Tabs` component from `components/admin/ui` for the
  Today/Inbox/Departments/GM sub-nav -- it's exported there already but
  no page uses it yet (email/social predate it with their own bespoke
  tab components). Flagged this choice in the drafts' NOTES.md in case
  you'd rather match the older pattern instead.
- Three small edits still needed on existing files (exact diffs in
  NOTES.md): a new `hq.view` permission (owner/admin, same tier as
  `audit.view`) in `lib/admin-permissions.ts`, a new icon in
  `components/admin/icons.tsx`, and the nav entry in
  `components/admin/nav-config.ts`.

I couldn't run a real build or typecheck from here either (`node_modules`
in this worktree isn't readable from this sandbox -- `Input/output error`
on `ls`), so I did a careful manual pass against the actual surrounding
